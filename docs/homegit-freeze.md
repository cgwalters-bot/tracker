## The operator's steps, in order

The operator-action schema is in [cgwalters-forge/agent-board's docs/operator-actions.md](https://github.com/cgwalters-forge/agent-board/blob/main/docs/operator-actions.md); these steps remain listed for the operator to run by hand.

**1. Stop the workstation controller.** Done on 22 Oct 2026: the units are stopped and disabled, with their files kept. The operator decided there will be no machine-specific supervisor; hosted polling and the review app's on-demand runs replace it. The original step: once the hosted poll has run a day
without failing. While both run, the sweep's `bot-watch --apply` and the
poll act on the same pull requests. This prints the conclusions of the last
day's polls; go ahead only
if it shows nothing but `success` and `cancelled`:

```sh
gh run list -R cgwalters-forge/tracker --workflow poll.yml -L 1000 \
    --created ">=$(date -u -d '24 hours ago' +%FT%TZ)" \
    --json conclusion --jq 'group_by(.conclusion) | map({(.[0].conclusion): length}) | add'
```

Then continue on the workstation. The supervisor's unit kills every process in its
cgroup, including local `bot-claude` jobs, so first check that none is running:

```sh
systemd-cgls --user -u bot-supervisor.service
systemctl --user disable --now bot-supervisor.service bot-sweep.timer
systemctl --user stop bot-sweep.service
systemctl --user list-units --all 'bot-*'   # nothing active
```

Keep `~/.config/bot-supervisor.env` and the token file it names:
[bring-up.md](bring-up.md) starts every shell from them.

**2. Run the broker from its own repository's quadlets.** Done on 20 Oct 2026: the broker runs from its own deployment and serves all inference; the old host's quadlets are stopped and disabled, with their volumes kept for rollback. The original step: The two copies
differ. homegit's (last changed 1 Oct) runs the upstream
`ghcr.io/praxis-proxy/ai` image pinned by digest with a `praxis.yaml`
mounted from the broker checkout, publishes ports 18080 and 18083 on
`$BROKER_ADDR` itself and is limited to `ConditionHost=` the old host. The broker's
(12 Oct) runs its own `-gateway:main` image with the Claude token as a
Podman secret, follows `:main` with `AutoUpdate=registry`, and publishes
only `127.0.0.1:18080`: the tailnet address and the run registration policy
are drop-ins. 18083 is gone, replaced by the `/anthropic` routes on 18080.
The broker's `INTERNALS.md` ("Quadlet") is the reference. See which copy is running:

```sh
systemctl --user cat praxis-credential-broker-pod.service praxis-credential-broker-praxis.service |
    grep -E 'SourcePath|PublishPort|Image=|run-token-policy'
```

If `SourcePath` is under the broker checkout's `contrib/quadlet`, and the
output has `PublishPort=$BROKER_ADDR:18080:8081` and the policy's
`Volume=`, its copy is running: skip to the check at the end. Otherwise
homegit's copy is running, installed in `~/.config/containers/systemd/praxis-credential-broker/`
(if `SourcePath` names another directory, set `OLD` to it). Pull the broker
checkout only now: homegit's gateway reads its `praxis.yaml`. Write
`~/.config/praxis-credential-broker/run-token-policy.yaml` first, listing
this repository's dispatch workflow as the broker's "Run tokens" section
says, without `unproven`. Then stop the pod, store the secrets
`podman secret ls` does not list yet, swap the units and start it:

Set `BROKER_ADDR` to the broker host's tailnet address, which is kept in the
operator's private notes rather than here.

```sh
B=~/src/github/cgwalters-bot/praxis-credential-broker
OLD=~/.config/containers/systemd/praxis-credential-broker
git -C $B pull --ff-only
diff -ru "$OLD" $B/contrib/quadlet
systemctl --user stop praxis-credential-broker-pod.service
podman secret ls
bash $B/scripts/init-secrets               # if praxis-credential-broker-agent-channel is missing
bash $B/scripts/init-anthropic-token       # if praxis-credential-broker-anthropic-oauth is missing
bash $B/scripts/init-mistral-key           # if praxis-credential-broker-mistral-api-key is missing
rm "$OLD"/praxis-credential-broker*.pod "$OLD"/praxis-credential-broker*.container \
    "$OLD"/praxis-credential-broker*.volume && rmdir "$OLD"
cd ~/.config/containers/systemd
ln -s $B/contrib/quadlet/* .
mkdir -p praxis-credential-broker.pod.d praxis-credential-broker-praxis.container.d
cat > praxis-credential-broker.pod.d/tailnet.conf <<EOF
[Pod]
PublishPort=$BROKER_ADDR:18080:8081

[Service]
ExecStartPre=/usr/bin/tailscale wait --timeout=30s
ExecStartPre=/usr/bin/tailscale ip --4 --assert=$BROKER_ADDR
EOF
cat > praxis-credential-broker-praxis.container.d/run-token-policy.conf <<'EOF'
[Container]
Volume=%h/.config/praxis-credential-broker/run-token-policy.yaml:/etc/praxis-credential-broker/run-token-policy.yaml:ro,Z
EOF
# The mistral pool uses /mistral.
cat > praxis-credential-broker-praxis.container.d/mistral-api-key.conf <<'EOF'
[Container]
Secret=praxis-credential-broker-mistral-api-key,target=/run/secrets/mistral/api-key,uid=65532,gid=65532,mode=0400
EOF
QUADLET_UNIT_DIRS=~/.config/containers/systemd /usr/libexec/podman/quadlet -dryrun -user
systemctl --user daemon-reload
systemctl --user start praxis-credential-broker-pod.service
```

Check: `curl -fsS http://$BROKER_ADDR:18080/healthz`, then a dispatched
run that reaches inference.

#### Matching, attribution and existing evidence

At broker `b57ff815cfd68196ead02adf4db047f41a704088`, the
[called-workflow matcher](https://github.com/cgwalters-bot/praxis-credential-broker/blob/b57ff815cfd68196ead02adf4db047f41a704088/crates/praxis-gateway/src/oidc.rs#L168-L242)
separates `job_workflow_ref` (workflow path and ref) from `job_workflow_sha`
(resolved commit). A policy `ref: refs/heads/main` follows moving code; a `sha`
condition fixes the commit. A SHA-only entry accepts a full `refs/...` or SHA
ref spelling but still checks the SHA claim; specifying both requires both.
Tracker's literal `@main` is therefore not a commit pin even though this
observation resolved it. The pinned review caller has a different ref spelling
from the three main callers, even when their resolved commits coincide.
Called-workflow caller restrictions use repository/owner IDs from the calling
repository; events are unrestricted unless explicitly restricted.

The [admission alternatives and consumer selection](https://github.com/cgwalters-bot/praxis-credential-broker/blob/b57ff815cfd68196ead02adf4db047f41a704088/crates/praxis-gateway/src/oidc.rs#L250-L300)
try `workflows`, `called_workflows`, then `any_workflow`. `workflows` checks an
exact job workflow ref and by default requires the entry workflow to match it
(or checks configured `entry_workflows`). `any_workflow` can admit every workflow
and ref from selected owner/repository IDs, or any repository. These are OR
paths: adding a narrow entry does not override broader admission. The
[example policy](https://github.com/cgwalters-bot/praxis-credential-broker/blob/b57ff815cfd68196ead02adf4db047f41a704088/run-token-policy.yaml)
also describes `unproven` registration without OIDC, where network access is the
gate. None of these source capabilities proves which route is deployed.

The admitting entry selects the `consumer`, so overlapping broad/narrow entries
can change budget attribution as well as admission. The broker
[retains admission and identity claims](https://github.com/cgwalters-bot/praxis-credential-broker/blob/b57ff815cfd68196ead02adf4db047f41a704088/crates/praxis-gateway/src/oidc.rs#L353-L381).
Relevant existing tests (read, not executed in this documentation change) are
[`an_entry_must_say_what_it_admits`](https://github.com/cgwalters-bot/praxis-credential-broker/blob/b57ff815cfd68196ead02adf4db047f41a704088/crates/praxis-gateway/src/oidc.rs#L598-L700),
