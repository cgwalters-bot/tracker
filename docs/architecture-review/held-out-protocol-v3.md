## Why a new version

The version 2 discovery ran and selected one PR of five
([log](held-out-v2-selection.json)). Fourteen of its rule 6 rejections came from
an implementation defect: the base was computed as the merge base with the
base branch's *current* tip. For a PR merged with a merge commit that is the
reviewed commit itself, so the comparison was `identical` instead of the
historical fork point the rule means. That attempt saw metadata only (no
feedback bodies; one diff was hashed, not read). It is kept as abandoned
evidence, not patched and not counted.

This version was written after seeing version 2's metadata-only outcomes, so
it is not blind to them. Its changes fix how the base and failed requests are
computed; they add no judgement and do not depend on expected matches.

## Changes

1. **Base.** The base is the merge base of the reviewed revision and the PR's
   recorded `base.sha` (the base branch tip GitHub stored for the PR), not the
   branch's current tip. If the comparison from that base to the reviewed
   revision is not `ahead`, rule 6 rejects the PR as before.
2. **Failed metadata.** A review or inline record without a commit ID cannot
   anchor a revision: rule 5 rejects the PR. A metadata request that fails
   while a rule is being checked rejects the PR under that rule, with the error
   recorded; it is not retried.

Discovery repeats version 2's three searches and round-robin order with a
fresh retrieval; the same PRs may appear again and are examined from scratch.
