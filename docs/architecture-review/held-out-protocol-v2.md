# Held-out architecture evaluation protocol, version 2

> This text was generated by an LLM ([how cgwalters uses LLMs](https://github.com/cgwalters/cgwalters#llms)). cgwalters has not reviewed it yet.

Part of #1300 and #1224. Version 1 ([protocol](held-out-protocol.md),
[ledger](held-out.json)) froze a sample and then recorded four deviations from
its own rules. Those are not waived: the version 1 sample stays an unfinished,
unreviewed checkpoint and development evidence, like the #1227 pilot. This
version resolves them prospectively by stating each rule before any new
discovery request, and draws a new sample under it. Its ledger is
[held-out-v2.json](held-out-v2.json), which records the SHA-256 of this file,
the [scoring rubric](held-out-v2-rubric.md) and the shipped prompt/library, and
the time they were frozen. Any later change to this file or the rubric requires
version 3 and a new sample.

The concrete threat is unchanged: feedback, labels or later fixes reaching a
historical review and making apparent recall meaningless. The single mechanism
is still an explicit exact-manifest packet given to a fresh context with no
tools, scored afterwards by a separate fresh context. Hashes detect changed
bytes, not prior knowledge or model training exposure. This is a manual
procedure: off by default, no production caller, no new option or permission.

## Frozen inputs

The reviewer receives prompt.md, patterns.md and references.json byte for byte
as of tracker revision 2665dbb77eda413f593238d432fb6323cf6bd62d, with the
SHA-256 values already pinned by version 1. The structural check reads them
from that revision with git and compares them to the working tree. No prompt or
library change is made on or after this sample.

## Retrieval

All retrieval uses the environment's authenticated `gh` client and only reads:
REST GETs and GraphQL queries, never mutations. Authentication raises rate
limits and allows GraphQL; it does not grant write access to anything here.
Each request has a 20-second timeout and an 8 MiB response limit. Paginated
channels read at most 10 pages of 100 records; reaching the cap without a
short final page makes that channel incomplete, and the PR ineligible.

Before review, the controller process may receive review and comment records
in order to read their metadata (author, timestamps, commit IDs). It discards
their text in memory, never prints or writes it, and archives only metadata.
Feedback bodies are fetched again, complete, only after every review output is
archived.

## Discovery

Three searches, in this order, each `GET /search/issues` with 20 results per
page, page 1, sorted by creation ascending:

    repo:REPO is:pr is:merged reviewed-by:cgwalters -author:cgwalters -involves:cgwalters-bot merged:2026-07-01..2026-11-04

for REPO = bootc-dev/bootc, ostreedev/ostree, composefs/composefs. That caps
discovery at 60 PRs. The window starts after the reviewing model's stated
training cutoff (June 2026); this lowers training exposure but cannot rule it
out. A failed or incomplete search is archived and its repository contributes
no candidates; it is not retried with another query. Archive the query,
retrieval time, total count, `incomplete_results`, and per result the number,
author, creation and merge time and a hash of the search record.

Candidates are examined round-robin by rank: rank 1 of each repository in the
order above, then rank 2, and so on. Examination stops at the fifth accepted PR
or at the end of the list.

## Eligibility

Every rule below uses metadata only and is applied in this order; the first
failing rule is the recorded reason. No title judgement, body or diff content is
used, so the selection can be recomputed from the archived metadata.

1. **Exclusions.** Not in sample.json (accepted and rejected pilot PRs), the
   version 1 derivation inventory, the version 1 discovery list (all 40 PRs,
   including the five frozen ones), or any PR or issue number in these three
   repositories named in tracker files, tracker commit messages, or issues and
   comments of #1224, #1227, #1300 and #1303 (archived in the selection log).
2. **Operator authorship.** cgwalters is not the PR author. On his own PRs his
   records are author replies, not review, so they never qualify. The bot is
   excluded through `-involves:cgwalters-bot`: its sessions may have read the
   feedback.
3. **Automation.** The author is not a bot account (`type` Bot or a login
   ending in `[bot]`).
4. **Complete channels.** cgwalters review records, inline comments and PR
   comments are each read completely within the page cap.
5. **Reviewed revision.** He submitted at least one review. First feedback is
   his earliest record in any channel. The reviewed revision is the commit ID of
   his earliest review (or inline comment, whichever is first). If one of his
   PR comments is strictly earlier than both, the revision under discussion is
   ambiguous and the PR is ineligible.
6. **History.** The base is the merge base of the PR's base branch and the
   reviewed revision. The comparison must be `ahead`, list every commit (at most
   250) and fewer than 300 files, and every commit and the base must be
   committed no later than first feedback.
7. **Architecture proxy.** Code paths are changed files not under `docs/`,
   `doc/`, `tests/`, `test/`, `ci/`, `hack/`, `contrib/`, `.github/`, `tmt/`
   or any `tests/` directory, and not ending in `.md`, `.txt`, `.adoc`,
   `.lock`, `.sum`, `.toml`, `.yml`, `.yaml` or `.json`. A code path's
   component is its first directory, or its first two for paths under `crates/`,
   `src/`, `lib/` or `rust/` with at least three parts; a top-level file is
   component `.`. Qualifying PRs change at least two components and at least 40
   added plus deleted code lines. This is a coarse proxy for "changes a
   cross-component contract", chosen because it needs no judgement; it will
   admit some local changes and miss some contract changes.
8. **Packet fits.** The annotated diff plus `identity.md` fits in 30 files and
   100,000 UTF-8 bytes, counted exactly as below. The diff is never truncated.

Archive every examined PR with its decision, failing rule, metadata source and
the metadata the rules used. Freeze the five identities, revisions and bases in
the ledger before any packet is handed to a reviewer. If fewer than five qualify,
the evaluation is incomplete; no rule is relaxed and no other PR is borrowed. A
selected PR stays in every denominator even if it later yields no scorable root.

## Historical packets

The builder is the Justfile's existing `select`/`readPacket`/`comparePacket`
code with these explicit rules, which version 1 applied without stating them:

- **Non-UTF-8 sources.** A changed file at the reviewed revision that is not
  valid UTF-8 is omitted whole, with path, revision, size and reason in the
  manifest; the diff still records that it changed. No lossy decoding.
- **Historical identity.** `identity.md` holds the repository, the title as of
  first feedback (from rename events) and the description verbatim when it was
  never edited at or after first feedback; otherwise it is left out and the
  manifest says why. It follows `diff.patch`, is never omitted, and its bytes
  and file count are part of the 30-file and 100,000-byte limits.
- **Reviewer-visible header.** The controller adds a header naming BASE, HEAD,
  each packet file with its size and SHA-256, and each omission (path, size,
  reason). It is generated from the manifest, and its bytes are archived by hash
  with the request; first-feedback time, selection reasons and the manifest
  itself stay controller-only.
- **Guidance.** Project guidance files are not supplied unless they are among
  the changed files.

Packets are published only after a clean reconstruction matches the archived
manifest; a second build must reproduce it.

## Isolated review

One review per PR. The controller starts the environment's own headless
client, reading the inference address, model and credential only from the
environment (never archived), in a new empty working directory and HOME, with
no tools, no MCP servers, no setting sources, no session persistence and no
GitHub credential. The client's initialisation record must show an empty tool
list; otherwise the run is excluded. The model therefore has no network,
filesystem or controller context, only:

- the system prompt `You are a read-only reviewer. The user message contains
  the complete review procedure and the material to review.`, after the fixed
  identity line the client prepends (its exact bytes are not observable);
- one user message: prompt.md, patterns.md and references.json in that order,
  then the header, then each packet file in manifest order, each part opened by
  a `===== FILE: name =====` line.

Archive the message assembly, the SHA-256 of every part and of the whole user
message, the client version, flags, model, run ID, start and end times, cost,
the initialisation record's tool list and the verbatim output with its hash,
all before any feedback body is fetched. Bounds: 20 minutes and US$5 per run.
A run that returns no output because of an infrastructure error may be retried
once; both attempts are archived. A run with output is final, whatever it says.
No retry is chosen for score.

## Scoring and noise audit

After all outputs are archived, fetch the complete paginated cgwalters inline
comments, review bodies and PR comments for each PR, verbatim with IDs, URLs,
creation and edit times and commit IDs, and archive them. One fresh scorer run
per PR, isolated like the reviewer, receives the frozen rubric, the review's
packet, the verbatim review output and that feedback snapshot, and returns the
rubric's JSON. A scorer reply that is not valid JSON may be retried once; both
are archived. Same per-run bounds.

The controller then checks the scorer's JSON for internal consistency and the
evidence of every caught, partial or disputed root and every audit disposition.
Where it disagrees it records both rationales and leaves the match disputed;
it does not rewrite the scorer's result. Lower and upper counts exclude and
include disputed matches.

Report per PR, then in total: discovered, examined, selected, packet-complete,
attempted, completed, contaminated and scored PRs; feedback records by channel
and class; unique concern and question roots, scorable, unscorable, caught,
partial and missed; raw, unique and duplicate findings; matched, unmatched and
audited supported/unsupported/unresolved findings. Each rate carries its
numerator and denominator; an empty denominator gives null, not zero. Five
purposively selected PRs cannot establish population performance and roots in
one PR are not independent. All scoring is agent-only, not human adjudication,
and no production activation or effectiveness recommendation follows from it.

## Stopping rules

Stop and record the evaluation as incomplete, without fabricating any review or
score, if inference or isolation is unavailable, fewer than five PRs qualify,
a packet cannot be reproduced, or the total spend would exceed US$60. Stop and
exclude a run, keeping it as evidence, if it is contaminated (any feedback,
label, later commit or controller summary reached it, or its tool list is not
empty). Never replace a selected PR, rerun a completed review, or tune the
prompt, library or rubric on this sample.
