## Recovered executable packet recipe

The concrete threat addressed here is a retrospective result silently scored
against a different input packet. The existing explicit read-only packet remains
the one mechanism, off unless manually invoked. No production caller, option or
automatic task is added. Default verification and fixtures are offline; network
retrieval is explicit `rebuild` or `feedback` mode in the existing Justfile recipe.

From the repository root, `just test-architecture-review rebuild B2588`:

1. Reads the frozen sample and manifest, never a moving PR head. GETs
   `repos/REPO/compare/BASE...HEAD` with JSON Accept and
   `X-GitHub-Api-Version: 2022-11-28`. Requires `ahead`, merge-base SHA equal to
   BASE, complete commit list equal to archived SHA/date list, and every
   committer timestamp at or before frozen first feedback. A 300-file list is
   refused as potentially truncated; compare commit truncation is detected by
   `total_commits != commits.length`. Dates/ancestry do not establish blinding.
2. GETs the same pinned compare endpoint with
   `Accept: application/vnd.github.diff`. Decodes strict UTF-8 preserving BOM,
   CR, LF and terminal-newline presence. Splits on LF, rejoins with LF; no trim,
   newline insertion, HTML escaping or Unicode normalization. On each `@@` hunk
   header set a counter to `+new-start`. Prefix following context/addition lines
   with the new-side decimal counter right-aligned to width four, then one
   space; increment counter. Deletions get four spaces plus separator space,
   without increment. Headers and `\ No newline at end of file` stay unprefixed;
   reset at `diff --git`. Encode UTF-8 as `diff.patch`. All three diff digests,
   including B2603's deletions, match: not merely a plausible new format.
3. For every nonremoved changed path, GETs
   `repos/REPO/contents/ENCODED_PATH?ref=HEAD` as JSON, encoding each path segment.
   Requires base64 file content; decodes and checks API `size`. Renames use new
   paths; removed files have diff only. Invalid UTF-8 fails rather than replacing
   bytes. Responses are limited to 8 MiB and 20 seconds each. No reviewed code runs.
4. Places complete annotated diff first; refuses if it alone exceeds the packet
   limits. Sorts HEAD files by decoded byte length, then UTF-8 path bytes for
   ties. Maps `/` to `__` under `head/`; refuses mapping collisions. Adds whole
   files while both limits allow, skipping, not truncating, nonfitting files.
   Diff consumes one file slot. Omissions record path, HEAD, source byte size
   and archived reason string. Library/prompt/index/manifest metadata are outside
   the reviewed-material budget, as in the original manifests.
5. Requires reconstruction comparison to match before writing a fresh sibling
   staging directory. Checks staged bytes and exact entries, then replaces the
   whole `/tmp/opencode/architecture-review-ID/` tree, removing any stale HEAD or
   feedback material. Writes separate `runs/ID.rebuild.json` only after packet
   publication, with expected/actual sizes and SHA-256 digests for **every**
   archived file, total, order, omissions and ancestry. Retrieval/comparison
   failure does not publish a new packet or success report. Existing evidence is left
   alone, not certified by that failed attempt. Staging is cleaned on failure.
   Old manifests/outputs/hashes never change. Reports, not sources, are archived.
6. `verify ID` requires exactly the manifest's regular files and their necessary
   directories: root `diff.patch`, plus `head/` with exactly the listed flat HEAD
   filenames if any. No other files/directories or symlinks, including at root,
   are allowed. It then checks byte counts and hashes without network. Exact
   directory integrity stops extra context that listed-file hash checking alone
   misses; neither check proves historical blinding or recomputes selection.
   This manual workspace is not designed for concurrent writers/readers during
   replacement.

The tie rule and collision refusal make unexercised cases explicit, not a claim
that the ephemeral original handled them identically. GitHub can change diff
rendering at pinned revisions; hashes detect that but do not make the service immutable.
This is a small textual-packet builder, not a binary/submodule corpus collector.

## Explicit rubric

Classify design concerns, questions/tradeoffs, local nits/test suggestions and
acknowledgements/empty bodies separately. Split independent roots in a mixed
comment; deduplicate alternative remedies and repeat descriptions of one cause.
Match only the same concern and affected component/evidence at frozen revision,
not shared pattern IDs or terminology. Partial overlap earns no full-match
credit. Questions matching tradeoffs stay in that stratum, never caught defects.
Count each root caught at most once. A question can be raised without proving
its answer; an absent historical policy makes a concern unscorable, not missed.
Unmatched findings are not automatically false: audit and report
supported/unsupported/unresolved over the audited denominator. Operator feedback
is not an exhaustive bug oracle. Static support does not validate all scenarios,
severity or remedies. This rubric was provided explicitly to the second scorer.
