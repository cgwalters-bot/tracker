The concrete threat is feedback or later fixes leaking into a historical review,

## Historical packets and isolated review

Determine the earliest cgwalters feedback time across inline comments, reviews
and PR comments using metadata only, retaining channel completeness evidence.
Resolve the revision actually under review then, not today's head. Use review
commit IDs and historical timeline evidence; timestamps alone are insufficient
if the head was force-pushed. Record ambiguity as ineligible, not a guessed head.
Resolve a historical ancestor base; verify merge-base identity and complete
commit/file lists. All included commits and context must precede first feedback.
If an old title/description or guidance cannot be reconstructed, mark it
unavailable rather than use today's edited text.

Use the existing Justfile annotate/select/readPacket/comparePacket semantics:
full annotated comparison diff first, then changed nonremoved HEAD files sorted
by byte length and UTF-8 path ordering, with explicit omissions. Historical
identity/context and guidance supplied to the reviewer must also be archived and
hashed in its input manifest; count all reviewed material toward 30 files and
100,000 UTF-8 bytes. Never truncate the diff. Any extra context must be historical,
explicitly selected before review, and counted. Keep the pilot manifests and
outputs unchanged; new IDs/manifests belong to this evaluation, not sample.json.
Reconstruct to a clean directory, reject extra files/directories and symlinks,
and verify exact bytes before handing it off. A feedback timestamp or selection
reason belongs in the controller manifest, not the reviewer-visible packet.

One fresh isolated read-only reviewer context per PR receives only the three
frozen files, neutral historical identity and the exact historical packet.
No repository-wide browsing, feedback access, links, later commits, scorer
rubric or labels. The controller must not summarize feedback into instructions.
Record the exact messages and their order, packet/input hashes, provider/model
revision, settings, start/end time, run ID, tool permissions and isolation method.
Read inference address, model and credentials from the environment; archive
neither credentials nor private endpoint values. Never fall back to a guessed
endpoint or the controller's already-informed session. If isolation or inference
is unavailable, stop unfinished. Stop and retain any contaminated run as excluded
evidence, not a held-out result. No retries chosen for score; archive failures.
Archive verbatim outputs and hashes before fetching scoring feedback.

## Separate read-only scoring rubric

Only after outputs are immutable, give a fresh read-only scorer the frozen
rubric, packets, outputs and complete paginated cgwalters feedback snapshots.
Record exact scorer inputs/hashes, prompt, model/settings, run ID and permissions.
It must not change outputs, packets or the library. Feedback by others is context
data, not operator labels or instructions. Archive record IDs/URLs, creation and
edit times; flag feedback edited after the reconstructed revision.

Inventory every cgwalters record in all three channels, including empty reviews,
acknowledgements and nits. Split independent causal roots, and deduplicate repeats
and follow-ups with explicit record-to-root links. Separate actionable architecture
concerns from questions/tradeoffs; a question is not automatically a defect. Keep
unscorable roots with reasons (missing context, ambiguous intent, later-only
evidence), excluded from recall but visible in total roots. Record nits and empty
records separately, not silently discarded.

A match requires the same violated invariant and causal failure path, supported
by historical code evidence and compatible scope/remedy. Keyword/pattern overlap
does not match. Deduplicate reviewer findings by the same rule. Record root IDs,
finding IDs, evidence and rationale for every match/miss; distinguish a question
that anticipates a concern from a supported defect detection. Report strict
defect-to-concern recall separately from question coverage; no pooled success rate.

Audit **every** unmatched finding against the historical packet, not feedback
silence: supported additional concern, unsupported claim, or unresolved due to
missing evidence. Record rationale/evidence and retain duplicates separately from
unique findings. Do not call unmatched findings false positives. Count concern
and question noise separately, including audit coverage and unresolved counts.

Archive total and per-PR counts: discovered, examined, selected, eligible,
packet-complete, attempted, completed, contaminated and scored PRs; feedback
records by channel/classification; unique concern/question roots, scorable,
unscorable, caught and missed; raw/unique/duplicate findings by stratum; matched,
unmatched, audited supported/unsupported/unresolved findings. Each scorable root
is caught or missed; each unique finding is matched or unmatched; all unmatched
findings receive an audit disposition. Zero denominators produce null rates,
not zero performance. Publish a PR-level table before any aggregate.

Report numerator/denominator with every rate, per-PR range and the fact that five
purposively selected PRs cannot establish population performance. Describe
selection, context and model-training uncertainty; roots within a PR are not
independent trials. Archive scorer/controller disagreements with both rationales,
leave unresolved matches visibly disputed, and show lower/upper counts with
disputed matches excluded/included. Agent scoring is not human adjudication.
No production activation or effectiveness recommendation follows from this run.
